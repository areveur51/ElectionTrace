Methods

Precinct flags are a separate queue. Every detector is the same rule in every state that has geometry. Ranked by how many precincts hit it here.

Reproduce a proof

The SHA-256 on View JSON is a checksum of that detector packet (the published numbers used, the thresholds, and the pass/fail checks). It is not a hash of the NYT GeoJSON, and it does not certify the detectors. Same extract, same item, same workup → same SHA.

  1. Clone the repo, fetch the data-2020 pack, and start the app: 
    git clone https://github.com/areveur51/ElectionTrace.git
cd ElectionTrace
npm install
./scripts/fetch-data.sh
npm start
  2. Precinct: open the same GEOID, or GET /api/precincts/<GEOID>/workup, and compare the sha256 field. Do not hash the downloaded file as a whole — that JSON already contains the digest.
  3. Night-of / In the files: open the same card, click View JSON, and compare sha256. Those packets hash the night-file inputs and checks, not the raw state JSON bytes.

Written steps: docs/REPRODUCE.md.

State first-digit check (Benford)

Applied identically to every state’s votes_total list in the precinct extract. Precinct totals often sit in a narrow band, so a state’s first-digit distribution can depart from Benford when totals cluster. A large departure is the state’s digit pattern.

Drop *.geojson.gz files in media/, then npm start. Index rebuilds when those files change.
